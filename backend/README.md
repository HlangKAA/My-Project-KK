# Backend feature map

Flask is registered in `app/__init__.py`. React provides the game screens; Flask provides JSON APIs and two HTML pages: the email verification result and Swagger UI.

| Feature | Files |
| --- | --- |
| Signup, login, reset and verify | `app/auth/routes.py` |
| Verification and password-reset mail | `app/auth/email.py` |
| Profile, onboarding, account deletion | `app/auth/account_routes.py` |
| Shared auth blueprint | `app/auth/blueprint.py` |
| Password validation | `app/auth/password_policy.py` |
| Submission and progress logic | `app/game/progress.py` |
| Leaderboard query | `app/game/leaderboard.py` |
| Game API routes | `app/game/routes.py` |
| Database connection | `app/db.py` |
| OpenAPI schema and Swagger page | `app/api_docs.py`, `app/main/routes.py` |

`app/game/catalog.json` and `seed_game_catalog.sql` are generated by `node scripts/export-game-catalog.mjs` from the repository root. Do not edit them manually. `REGIONS` in frontend stage data defines playable stages; retired stage rows remain in the database to preserve old submissions.

Credentials belong in `backend/.env`, which is ignored by Git. A complete empty-database bootstrap is not currently in this repository; seed SQL only updates catalog data after the current schema exists. Check database state before applying SQL to a live Supabase project.

Run `venv/Scripts/python.exe -m compileall -q app` from `backend/` for syntax checking and `venv/Scripts/python.exe -m unittest discover -s tests` for route contracts.
